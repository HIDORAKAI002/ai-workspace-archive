# Technical Documentation Template

Create clear, comprehensive technical documentation that developers actually want to read.

## Template

```xml
<task>Write technical documentation for this feature/product/API</task>

<subject>
[What needs to be documented: feature, API, library, system, etc.]
</subject>

<technical_details>
[Paste code, specs, requirements, or describe what needs documenting]
</technical_details>

<audience>
[Who will read this: frontend devs, backend devs, DevOps, all developers, etc.]
</audience>

<thinking>
Plan documentation:
1. What does the reader need to accomplish?
2. What do they already know?
3. What are the gotchas/pain points?
4. What examples will make this clear?
5. What's the quickest path to success?
</thinking>

<documentation_structure>
1. **Overview** - What it is, why it exists (30 seconds to understand value)
2. **Quick Start** - Get something working in 5 minutes
3. **Core Concepts** - Key ideas they need to understand
4. **Detailed Guide** - Deep dive with examples
5. **API Reference** - Complete technical details
6. **Troubleshooting** - Common issues and solutions
7. **FAQ** - Anticipated questions
</documentation_structure>

<writing_guidelines>
- Use active voice ("Click the button" not "The button should be clicked")
- Short paragraphs (3-4 lines max)
- Code examples for every concept
- Explain WHY, not just HOW
- NO jargon without explanation
- Include error messages user might see
- Show both success and failure cases
</writing_guidelines>

<output_format>
Provide complete technical documentation with:

1. **Title & Brief Description** (one sentence)

2. **Overview**
   - What this is
   - When to use it
   - Key benefits

3. **Prerequisites**
   - Required knowledge
   - Dependencies
   - System requirements

4. **Quick Start** (copy-paste ready)
   ```
   [Minimal example that works]
   ```

5. **Core Concepts**
   - Explain key ideas
   - Use analogies for complex topics
   - Include diagrams (describe if can't create)

6. **Detailed Usage**
   - Step-by-step instructions
   - Code examples with comments
   - Expected output

7. **Common Patterns**
   - Typical use cases
   - Best practices
   - Antipatterns to avoid

8. **Troubleshooting**
   - Common errors
   - How to debug
   - Where to get help

9. **API Reference** (if applicable)
   - Function signatures
   - Parameters and types
   - Return values
   - Examples

10. **FAQ**
</output_format>
```
